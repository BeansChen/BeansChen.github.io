# 1. 请说明Ajax、Axios、Fetch三者的区别

三者都用于网络请求，但是属于不同的维度

  • Ajax（Async JavaScript and xml），是一种 技术统称
    • 可以用 XMLHttpRequest 来实现
    • 也可以好用Fetch来实现

  • # Fetch，是一个原生的浏览器 API

  • Axios，是一个第三方 库
    • 内部可以用 XMLHttpRequest 来实现
    • 也可以好用Fetch来实现

目前网络数据传输有xml和json两种方式，目前大部分使用json进行网络数据传输。

xml更接近人类语言，可读性更强。json更像一个数据块，读起来费解，但是适合机器阅读。

# 2.节流和防抖

  • 防抖：触发高频事件n秒内只执行一次，如果n秒内高频事件再次触发，则重新计算时间，应用场景为提交按钮，手机验证码发生、邮箱验证码发送、实时保存、表单实时验证等
  • 节流：高频事件触发n秒内只执行一次，用于稀释函数的执行频率。应用场景有window的resize、scroll事件，drag事件。
  function debounce(fn, delay = 200) {
    let timer = 0

    return function () {
      if (timer) clearTimeout(timer)

      timer = setTimeout(() => {
        fn.apply(this, arguments) // 透传 this 和参数
        timer = 0
      }, delay)
    }
  }        
  function throttle(fn, delay = 100) {
    let timer = 0

    return function () {
      if (timer) return

      timer = setTimeout(() => {
        fn.apply(this, arguments)
        timer = 0
      }, delay)
    }
  }

# 3.px % em rem vw/vh的区别

  • px 是基本单位，绝对单位（其他都是相对单位）
  • % 相对于父元素的宽度比例
  • em 在font-size中相对于父元素字体大小，在其他属性中相对于自身的字体大小，如width
  • rem 相对于根节点的 font-size
  • vw屏幕宽度的1%，vh屏幕高度的1%,vmax是两者中的大值，vmin是两者中的小值

# 4.哪些情况不适用箭头函数

  • 箭头函数的缺点
    • 没有arguments
    • 无法通过call，apply，bind去改变this，箭头函数使用的是父节点的this
  • 哪些地方不用箭头函数
    • 对象方法
    • 对象原型
    • 构造函数
    • 动态上下文中的回调函数（btn.addEventListener('click',()=>{...})）
    • Vue的生命周期函数和methods（这个和对象方法是一个意思）

# 6.for-in和for-of有什么区别

  • for-in 遍历得到key，for-of 遍历得到value

  • 遍历对象：for-in 可以，for-of 不可以

  • 遍历Map、Set：for-of 可以，for-in 不可以

  • 遍历generator：for-of 可以，for-in 不可以

  • for-in 用于可枚举的数据，如字符串，对象，数组

  • for-of 用于可迭代的数据，如字符串，数组，Map，Set

# 7.for-await-of有什么作用？

用于遍历多个promise，某些情况下可以代替promise.all

  • 和promise.all的不同之处在于promise.all返回结果数组，而for-await-of返回的是结果
  • 在异常的情况下promise.all整体报错，而for-await-of单条报错并且不往下执行，但是前面的执行是成功的

# 8.offsetHeight-scrollHeight-clientHeight有什么区别

  • offsetHeight、offsetWidth：border+padding-content
  • clientHeight：padding+content
  • scrollHeight：padding + 实际内容尺寸（滚动容器）

# 14.HTTP跨域请求为什么要发生options请求

为什么会跨域：

  • 浏览器同源策略
  • 同源策略一般限制 ajax 网络请求，不能跨域请求 server
  • 不会限制<link> <img> <script> <iframe> 等加载第三方资源

JSONP跨域原理

    console.log(data)
  }
</script>

简单封装一个JSONP方法

  • 只能GET请求，这是script自身的限制决定的
  • 不能很好的发现错误，与Ajax相比，不能注册success，error事件监听函数
        !function (window, document) {
            var jsonp = function (url, data, callback) {
                // 处理参数
                var dataString = url.indexOf('?') > -1 ? '&' : '?'
                for (var key in data) {
                    dataString += key + '=' + data[key] + '&'
                }
                // 回调函数名字
                var callbackFnName = 'jsonp_callback_' + Math.random().toString().replace('.', '')
                dataString += dataString + 'callback=' + callbackFnName
                // 创建标签并赋值
                var scriptEle = document.createElement('script')
                scriptEle.src = url + dataString
                // 注册全局事件
                window[callbackFnName] = function (res) {
                    callback(res)
                    delete window[callbackFnName]
                    document.body.removeChild(scriptEle)
                }
                document.body.appendChild(scriptEle)
            }
            window.$jsonp = jsonp
        }(window, document)

CORS跨域原理

// CORS 配置允许跨域(服务端)
response.setHeader("Access-Control-Allow-0rigin",，"http://localhos:8011")// 或者*
response.setHeader("Access-Control-Allow-Headers""X-Requested-with" )
response.setHeader("Access-Control-Allow-Methods", "PUT,POST,GET,DELETE,OPTIONS")
response.setHeader("Access-Control-Allow-Credentials","true")// 允许跨域接收 cookie

为什么有options请求：

  • 跨域请求：当请求的目标与请求本身不同源时，会自动发出OPTIONS请求
  • 需要预检测的HTTP方法：如PUT、DELETE、POST等
  • 需要携带自定义头的HTTP请求

解决方法：

  • 服务端设置适当的CORS策略，允许相应的源、方法、头部
  • 如果不需要特殊的方法和头部，要满足简单请求的条件
  • NodeJS Express 示例代码
app.options('*', cors()); // 对于所有路径，设置CORS
app.all('*', cors());     // 设置CORS，允许所有源、方法和头部
 
function cors() {
  // 设置CORS的具体策略
  return function(req, res, next) {
    res.header('Access-Control-Allow-Origin', '*');
    res.header('Access-Control-Allow-Methods', 'GET, POST, OPTIONS');
    res.header('Access-Control-Allow-Headers', 'Content-Type, Authorization');
    // 预检请求的响应
    if ('OPTIONS' === req.method) {
      res.send(200);
    } else {
      next();
    }
  };
}
