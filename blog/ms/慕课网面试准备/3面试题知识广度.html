# 1. 移动端H5 click事件300ms的延迟怎么出现，如何解决？

因为手机 浏览器 double tap to room 这个功能，给300ms的延迟来判断是否要放大

  1. fastclick可以解决在手机上点击事件的300ms延迟
    • 监听 touchend 事件
    • 使用 自定义DOM事件 模拟一个click 事件
    • 再把默认的click事件禁掉
  2. zepto的touch模块，tap事件也是为了解决在click的延迟问题
  3. 现代浏览器只要viewport有width=device-width属性就不会有300ms延迟了（因为有这个属性浏览器认为你已经对移动端网页做了响应式布局了，不再需要这个延迟了）

1px像素如何实现

  1. 普通实现
#box {
  padding: 10px 0;
  position: relative;
}
#box::before {
  content:
  position: absolute;
  left: 0;
  bottom: 0;
  width: 100号;
  height: 1px;
  background: #d9d9d9;
  transform:scaleY(0.5);
  transform-origin:0 0;
}
  1. 有border-radius的情况
box-shadow:0 00 0.5px #d9d9d9;
  1. 现如今现代浏览器已经不用考率这个问题了，兼容性大都不错了

# 2.Token 和 Cookie 有什么区别

  • cookie和session配合使用，有跨域的限制

  • token和Jwt使用，无跨域限制

  • 如果有严格管理用户的需求，比如封禁用户，使用session（缺点是占用服务端的内存，有跨域限制，多进程时不好同步，要借助redis）

  • 如果没有其他特殊要求，推荐使用token（缺点是秘钥一旦泄露，会造成很大风险，token会增加请求体积）

# 4.HTTP协议和UDP协议有什么区别

  • HTTP是应用层，TCP UDP是传输层
  • TCP有连接，有断开，稳定传输
  • UDP无连接，无断开，不稳定传输，但是效率高

# 5.HTTP协议1.0 1.1 2.0有什么区别

1.0

  • 最基础的HTTP协议
  • 支持基本的GIT POST

1.1

  • 缓存策略 cache-control E-tag等
  • 支持长连接 Connection：keep-alive，一次TCP连接多次请求
  • 支持断点续传，状态码206
  • 支持新的方法 PUT DELETE PATCH等

2.0

  • 支持压缩header减少体积
  • 多路复用，一次TCP连接中可以多个HTTP并行请求（以前的优化策略，合并多个小文件为一个就无效了）
  • 服务端推送（ws）

# 9.Websocket和HTTP协议有什么区别

  • WebSocket的协议名是ws://，可双端发起请求
  • WebSocket 没有跨域限制
  • 通过 send 和 onmessage通讯（http通过 req和 res）

WebSocket和http长轮询

  • http长轮询：客户端发起请求，服务端阻塞，不会立即返回，须处理timeout，重新发起
  • WebSocket：客户端可以发起请求，服务端也可以发起请求

# 10.描述从url到页面展示的完整过程

  • 网络请求
    • DNS解析
    • 建立TCP连接（三次握手）
    • 浏览器发起HTTP请求
    • 收到响应，得到HTML代码
    • ...
    • 继续请求静态资源，图片、js、css
  • 解析
    • 从上之下依次解析
    • dom形成dom树，css形成css树，形成rendertree
  • 渲染：计算、绘制、同时执行JS

# 12.已经有了那么多后端语言，为什么还要nodejs ？

单线程，基于事件驱动，非阻塞，适合高并发服务

这些都是网上说的nodejs的好处，但是一个做java的人会因为这个好处选择nodejs吗，答案是不会的；

nodejs最大的优势是在于他使用JS语法，对前端工程师来说，学习成本很低，只需要熟悉一些nodejs即可以直接使用； 对于一些小系统，或者公司内部使用的不太复杂的项目，用nodejs来做不仅仅能降低人力成本，也能降低沟通成本，提高开发效率
