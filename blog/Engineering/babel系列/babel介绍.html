# 简介

Babel 是一个 JavaScript 编译器。主要用于将采用 ECMAScript 2015+ 语法编写的代码转换为向后兼容的 JavaScript 语法，以便能够运行在当前和旧版本的浏览器或其他环境中。借助Babel，可以方便使用下一代的 JavaScript 语法编程。

Babel 能为你做的事情：

  • 语法转换
  • 通过 Polyfill 方式在目标环境中添加缺失的特性 （通过引入第三方 polyfill 模块，例如 core-js (opens new window)）
  • 源码转换（codemods）

# 配置文件

# 文件类型

Babel 有两种并行的配置文件格式，可以一起使用，也可以单独使用。

  • 全局范围配置
    • babel.config.json文件，具有不同的扩展名 ( .js, .cjs, .mjs)
  • 局部范围配置
    • .babelrc.json文件，具有不同的扩展名 ( .babelrc, .js, .cjs, .mjs)
    • package.json 文件中key为"babel" 属性下配置

# 插件和预设

# 插件

# 插件的执行顺序

  • 插件在 Presets 前运行。
  • 插件顺序从前往后排列。
{
  "plugins": ["transform-decorators-legacy", "transform-class-properties"]
}

先执行 transform-decorators-legacy ，在执行 transform-class-properties。

# 预设（presets）

预设（preset）可以被看作是一组 Babel 插件。

# 预设的执行顺序

Preset 是逆序排列的（从后往前）。

{
  "presets": ["@babel/preset-env", "@babel/preset-react"]
}

将按如下顺序执行： 首先是 @babel/preset-react，然后是 @babel/preset-env。

# @babel/polyfill

babel默认只是转换新的语法，而不会转换新的API，比如 Promise、Map、Symbol、Proxy 等新的全局对象，或者是 Array.from 之类的新方法。

polyfill 就是提供这些环境不支持的特性的库。

@babel/polyfill 包含两个npm包 core-js 与 regenerator-runtime 。但从 Babel 7.4.0 开始，这个包已经被弃用，取而代之的是直接使用core-js/stable（以填充 ECMAScript 特性）和regenerator-runtime/runtime（生成器函数辅助函数）。

import "core-js/stable";
import "regenerator-runtime/runtime";

注意：再使用该方法的时候，就不应该安装 @babel/polyfill 了。 因为 @babel/polyfill 在安装的时候会自动安装core-js与regenerator-runtime这两个依赖，但是 @babel/polyfill 已经把 core-js版本锁定在2.x.x版本了，然而 core-js 已经发布到了3.xx版本， 2.x.x 版本并没有 core-js/stable ，所以引入会报错。

# 官方 polyfill 几种使用方式：

# 1.直接在浏览器中使用

可以在npm的 dist/polyfill.js 文件中拿到。可以把它包含在已编译的代码中，也可以添加在之前。

# 2. 在项目入口文件引入

比如 vue 的main.js文件，在该文件顶部引入

import "core-js/stable";
import "regenerator-runtime/runtime";

# 3.在webpack中引入

module.exports = {
  entry: ["core-js/stable', 'regenerator-runtime/runtime", "./src/main.js"],
};

# 按需加载 polyfill

搭配 @babel/preset-env (opens new window)和useBuiltIns选项 (opens new window)一起使用：

{
  "presets": [
    [
      "@babel/preset-env",
      {
        "useBuiltIns": "usage",
        "corejs":3
      }
    ]
  ]
}

会根据配置的浏览器兼容，以及你代码中用到的 API 来进行 polyfill，实现了按需添加。

{
  "presets": [
    [
      "@babel/preset-env",
      {
        "useBuiltIns": "entry",
        "corejs":3
      }
    ]
  ]
}

会根据配置的浏览器兼容，引入浏览器不兼容的 polyfill。需要在入口文件引入

import 'core-js/stable';
import 'regenerator-runtime/runtime';

# 常用的预设和插件

# 预设

Babel官方的preset很多，但我们实际可能会用到的其实就只有4个：

  • @babel/preset-env
  • @babel/preset-flow
  • @babel/preset-react
  • @babel/preset-typescript

一个普通的vue工程，Babel官方的preset只需要配一个"@babel/preset-env"就可以了。

# 插件

插件常用的就更少了，因为很多插件预设里面以及内置了

目前比较常用的插件只有@babel/plugin-transform-runtime

# @babel/plugin-transform-runtime

用于复用注入的辅助函数来减少代码的体积。如果没有此插件，那么项目每个文件内联辅助函数，造成最终文件体积过大。

安装为开发依赖：

npm install --save-dev @babel/plugin-transform-runtime

安装 @babel/runtime 生产依赖 ，作用于运行时：

npm install --save @babel/runtime

常规用法：

{
  "plugins": ["@babel/plugin-transform-runtime"]
}

默认选项

{
  "plugins": [
    [
      "@babel/plugin-transform-runtime",
      {
        "absoluteRuntime": false,
        "corejs": false,
        "helpers": true,
        "regenerator": true,
        "version": "7.0.0-beta.0"
      }
    ]
  ]
}

# core-js

false, 2,3或{ version: 2 | 3, proposals: boolean }, 默认为false.

例如['@babel/plugin-transform-runtime', { corejs: 3 }],

此选项需要更改用于提供必要运行时帮助程序的依赖项：

corejs选项 安装命令
false npm install --save @babel/runtime
2 npm install --save @babel/runtime-corejs2
3 npm install --save @babel/runtime-corejs3

# 技术细节

转换器transform-runtime插件做了三件事：

  • 自动移除语法转换后内联的辅助函数（inline Babel helpers），使用@babel/runtime/helpers里的辅助函数来替代。
  • 当代码里使用了core-js的API，自动引入@babel/runtime-corejs3/core-js-stable/，以此来替代全局引入的core-js/stable。
  • 当代码里使用了Generator/async函数，自动引入@babel/runtime/regenerator，以此来替代全局引入的regenerator-runtime/runtime。

这意味着什么？意味着，你可以使用内置的API，例如，Promise ，Set，Symbol等，无缝使用所有需要 polyfill 的 Babel 功能，没有全局污染。

上面讲到的 polyfill 引入方式适用于具体项目，它是在 Window 中添加了新方法。而这种引入非常开发适合库，避免库中的 ployfill 和实际项目中版本不同造成冲突。

确保安装 @babel/runtime 为生产依赖！！！
