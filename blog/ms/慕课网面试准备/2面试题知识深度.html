# 一 、JS 内存泄漏

# 1.垃圾回收

  • 引用计数
    • 循环引用时会有问题，没法清除
  • 标记清除
    • 从window开始上往下遍历，能找到的就保留，找不到的就清除

# 2.闭包是内存泄漏吗

严格来说闭包不是内存泄漏

  • 内存泄漏是指非预期的内存占用
  • 而闭包数据不被垃圾回收是属于预期之内的

# 4.内存泄漏的场景（Vue为例）

  • 被全局变量、函数引用，组件销毁时未清除
    • window.arr = this.arr
    • window.printArr = function(){console.log(this.arr)}
  • 被全局事件、定时器引用、组件销毁时未清除
    • setInterval(()=>{console.log(this.arr)})
    • window.addEventListener('resize',()=>{console.log(this.arr)})
  • 被自定义事件引用，组件销毁时未清除

# 5.WeakMap和WeakSet

// 代码1
ele1.addEventListener('click', handler1, false);
ele2.addEventListener('click', handler2, false);

// 代码2
const listener = new WeakMap();

listener.set(ele1, handler1);
listener.set(ele2, handler2);

ele1.addEventListener('click', listener.get(ele1), false);
ele2.addEventListener('click', listener.get(ele2), false);

//代码2比起代码1的好处是：由于监听函数是放在 WeakMap 里面，
//则一旦dom对象ele1,ele2消失，与它绑定的监听函数handler1和handler2 也会自动消失

# 二、浏览器和nodejs事件循环

# 1.单线程和异步

  • JS是单线程的
  • 浏览器中JS执行和DOM渲染公用一个线程

# 2.宏任务和微任务

  • 宏任务：setTimeout、setIntervel
  • 微任务：promise asyc/await
  • 微任务在下一轮DOM渲染之前执行，宏任务在之后执行

# 3.nodejs异步

  • nodejs的宏任务和微任务，分不同类型，有不同优先级

# 三、虚拟DOM真的快吗

vue数据驱动：

  1. data变化
  2. vnode diff
  3. 更新DOM

传统jquery：

  1. 找到更新DOM节点然后更新

总结：

  • 并不快，js直接操作DOM更快
  • 但是数据驱动要有合适的技术方案,不能全部重建DOM
  • vdom就是目前最合适的方案（并不是块，而是合适）

# 四、for和forEach哪个更快

  • 两者的时间复杂度都是O(n)
  • 但是forEach每次都要初始化一个函数调用
  • 函数需要独立的作用域，会有额外的开销
  • 越 “低级” 的代码，性能往往越好

# 五、请描述JS Bridge原理

  • JS无法直接调用native API
  • 需要通过一些特定格式来调用
  • 这些 格式 统称为 JS Bridge，例如微信的JSSDK

JS Bridge常见实现方式

  • 全局注册API
    • webview是app生成的，所以app可以在webview的window上添加一些属性
  • URL Scheme
    • 在移动应用中，应用程序可以注册自己的 URL Scheme，使得其他应用程序可以通过特定的 URL 格式来启动该应用程序并传递相关的数据。例如，微信应用程序注册了weixin://这样的 URL Scheme，其他应用程序可以通过调用weixin://这样的 URL 来启动微信并传递相关的数据

# 六、 Vue3的 Compostion API 生命周期有什么区别

  • 用 setup 代替了 beforeCreate 和 created
  • 使用 Hooks 函数的形式，如 mounted 改为了onMounted()

# 七、Vue2和Vue3和React三者的diff算法有什么区别

  • 只比较同一层级，不跨级比较
  • tag 不同则删除重建
  • 子节点通过key来区分

答案：

  • Vue2 - 双端比较
  • Vue3 - 最长递增子系列
  • React - 仅右移

Vue React 为何循环时、必须使用key？

  • vdom diff 算法会根据 key 判断元素是否要删除
  • 匹配了 key ，则只移动元素 - 性能较好
  • 未匹配 key ，则删除重建 - 性能较差

# 八、Vue-router 三种模式

  • Hash
  • WebHistory
  • MemoryHistory（V4 之前叫做 abstract history）
    • 类似于组件切换一样，url 路由不会变
