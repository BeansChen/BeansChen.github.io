# 1.常见的SPA性能优化方案有哪些

首屏优化的核心是加载和解析的性能

  • 加载优化的核心是 资源体积 和 首屏资源数量

  • 解析优化的核心是 资源体积 和 代码的执行性能

可见，资源体积会同时影响加载和解析性能，所以优化的第一个重点在于资源体积

加载优化：

加载优化最有效的方式在于缓存的使用，再快的网速再大的并发也抵不过直接跳过下载阶段。

其他的优化：

  1. 合理分包，利用Webpack的Code split探索出合适的包体积和资源数量
  2. 启用CDN加速，让不同地区的人享受稳定可靠的下载速度
  3. 静态资源分域，将图片、音视频等放到静态资源服务器，防止加载时受到浏览器并发数限制；同时还可以实现cookie隔离（降低header的数据包含，以达到加快访问速度的目的）
  4. DNS预解析：提前解析浏览器之后可能会用到的域名，将解析结果放到系统缓存中，这样做可以缩短DNS解析时间。
    • 静态资源域名
    • JS会发起跳转的域名
    • 重定向的域名
    • 不对超链接做预解析，浏览器会自动做
  5. 尽量启用HTTP2，HTTP2提供了多路复用可以突破并发限制，头部字段压缩也可以减少传输的数据体积，二进制数据传输也可以让多种数据类型选择更合适的方式传输

解析优化：

  • 资源体积优化
    • 压缩字体、图片、音视频文件体积等
    • 利用Webpack的Tree Shaking 技术,这就要求我们执行按需加载策略,并尽可能的使用 ES Module 方式去组织代码和选择三方代码的入口点
    • 利用异步方式延时加载非首屏资源
  • 运行时性能优化
    • 这就需要在日常开发中写出高质量代码了
    • 例如合理添加loading增强用户体验

# 2.常见的性能优化

  • 路由懒加载
  • 服务端渲染SSR
  • 分页
  • 图片懒加载
  • App预取（比如访问列表页，预加载文章首屏内容）
  • 还有体验上的优化：loading动画 和 骨架屏等

# 3.后端一次性返回 10w 条数据，你该如何渲染

  • 首先后端一次返回 10w 条数据，这本身设计上就不合理
  • 如果无法更改，那么方案有
    • 自己定义一个nodejs中间层，自己来处理数据
    • 虚拟列表
      • 只渲染可视区的DOM
      • 其他隐藏区域，用空白div撑起高度
      • 随着浏览器滚动，创建和销毁DOM
    • 前端自行分页
