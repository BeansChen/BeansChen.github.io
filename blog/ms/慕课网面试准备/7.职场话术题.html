# 如何处理沟通冲突？

冲突类型：

  • 需求变更
    • 可以啊，麻烦拉个会议讨论一下吧，看是否会影响工期
  • 项目延期：别人延期或自己延期
    • 及时告诉领导，项目因为什么原因可能会延期，不过我会尽量如期完成，先告知风险
  • 技术方案冲突：后端返回的接口格式不合理

# 如果你是一个项目负责人，你的主要职责是什么？

目标：

保证项目按时、按质量交付上线，以及上线之后的稳定运行

职责：

  • 把控需求
    • 需求评审
    • 深入了解业务
    • UI设计图评审
    • 开发排期
      • 开发时间
      • 测试时间
      • 预留缓冲时间
    • 插入新需求，需要重新排期
  • 技术方案设计
    • 核心数据结构设计
    • 核心流程设计
    • 核心功能的组织和实现
    • 和服务端接口约定
  • 开发
    • 通用代码
    • 核心功能
    • 底层逻辑
  • 监督代码质量
    • 制定代码规范
    • 定期code review
    • 自动化单元测试
  • 跟踪进度
    • 定期例会，收集当前的进度、风险和问题
  • 稳定安全的运行
    • 统计和监控功能
      • 流量统计
      • 性能统计
      • 错误监控
      • 及时报警

# 如果你是一个前端负责人，如何做技术选选型

# 选什么？

  • 前端框架（Vue、React、Angular等）
  • 语言（JavaScript、typescript）
  • 其他（构建工具、CI/CD等）

# 技术选型的依据

  • 社区是否成熟
  • 公司是否有积累
  • 团队成员的学习成本

# 要全面考虑各种成本

  • 学习成本
  • 管理成本（如用了TS遍地都是any）
  • 运维成本

# 如何做code review

  • 代码规范（eslint不能全检查，如变量名称‘ 如 var woDe = 1 ，代码语义（某些写法不好理解）’）
  • 重复代码抽离、复用
  • 单个函数过长，是否需要拆分
  • 算法复杂度是否可用，能否继续优化
  • 是否有安全漏洞
  • 扩展性如何？（不要为了扩展而扩招，保证不是封闭的就行，要根据实际情况来）
  • 是否功能重复实现了（比如项目里面有的功能重复写了）
  • 是否有完善的单元测试？
  • 组件设计是否合理？

什么时候code review

  • 提交 PR ，通过代码 diff 进行 code review
  • 每周例行一次cod review

持续优化

  • 每次code review 的问题要记录下来
  • 归纳整理，形成自己的代码规范体系
  • 新成员要提前学习规范，提前规避

# 如何学习一门新语言，要考虑哪些方面

  • 它的优势和应用场景
  • 语法
  • 内置模块和API
  • 常用的第三方框架和库
  • 开发环境和调试工具
  • 线上环境和发布过程

# 你觉得自己有哪些不足之处

  • 范围定在技术方面

  • 非核心技术栈

  • 要容易弥补的

  • 我觉的我自己在xxx方面存在不足

  • 但我已经意识到了，并且开始学习
