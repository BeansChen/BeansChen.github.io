    # 21.有以下三个判断数组的方法，请判断他们之前的区别和优劣？

    Object.prototype.toString.call()
instanceof
Array.isArray()
    1. 首先Object.prototype.toString.call() 会返回一个[Object type] 的字符串，其中包含了对象的类型，这种方法能判断所有的类型，用于判断内置对象，缺点是 不能判断自定义对象且要保证 toString 没有被重写
    2. instanceof 通过原型链中能不能找到类型的 prototype , 缺点是只能判断对象类型，不能判断原始类型，且不能跨 iframe
    3. Array.isArray() 的优点是判断数组很高效，且不会抛出错误。缺点是只能判断数组，不能判断类数组如 arguments

    # 22.介绍下重绘和回流，并说明怎么优化？

    1. 首先从网页的解析开始说起，网页的解析分为解析HTML生成DOM树，解析CSS生成CSSOM树，然后合两者生成renderTree，然后计算它们在页面的大小和位置，最会把节点绘制到页面上
    2. 其中重绘和回流就起到了很大的作用，重绘是指修改了元素的样式，但未修改元素几何属性，这个时候只需要重新绘制当前元素，而不需要重新布局。而回流是指修改了几何属性，导致浏览器重新布局。
    3. 优化方式有几种：
      1. 批量设置css 的 style 属性，或者使用class来一次修改多个元素的样式
      2. 使用文档片段批量插入DOM节点
      3. 动画效果应用到 abusolute 或者 fixed 元素上，以免影响其他元素
      4. 浏览器读取某些属性会导致回流，比如offsetLfet、scrollTop等，应尽量避免
      5. 使用transform代替设置top，opacity和visibility来代替display:none
      6. 使用节流和防抖函数来降低重绘回流频率

    # 23.介绍下发布订阅模式和观察者模式，以及他们各种适用于什么场景？

    1. 观察者模式里面有两个角色：观察者 和 被观察者，重点是被观察者。
    2. 发布订阅模式不只是有 发布者 和 订阅者 ，还有一个 事件中心 ，重点是事件中心。
    3. 观察者模式适用场景：
      1. GUI事件处理，比如DOM点击，鼠标移动
      2. 比如一个电商系统，下单的时候，可以同时通知库存系统，物流系统，支付系统做不同的处理
    4. 发布订阅模式适用场景：
      1. 比如消息中心，新闻网站，公众号之类的
    5. 总的来说就是一对多和多对多的区别。

    # 24.说一说 Vuex 和 Redux 的设计思想？

    1. react 了解的比较少，我这就聊一聊Vuex的设计思想吧

    # 25.说一说浏览器和node事件循环的区别？

    1. 这个我了解的比较少，就简单的说一说吧
    2. 首先浏览器的事件循环主要用于处理交互事件（点击事件，网络请求），而node的事件循环主要用于I/O操作（文件读取，网络请求）等
    3. 还有就他两的时间循环机制实现方式不一样，API也不一样
    4. 在Node端，microtask在事件循环的各个阶段之间执行（6个阶段）
    5. 而浏览器端，microtask在macrotask执行完之后执行

    # 28.cookie 和 token 放在 header 中，为什么 token 不会被劫持？

    1. 浏览器会自动带上 cookie，攻击者通过xss攻击可以拿到cookie，可以通过csrf攻击伪造请求
    2. 而token不会被浏览器自动带上，有效的避免 csrf 攻击
    3. cookie在有效期内一直可以使用，哪怕用户注销，而token可以设置一个较短的时间，然后通过refresh_token刷新机制去换取新的token
    4. token通过加密算法和签名算法来保护其内容，所以即使被拦截，攻击者也很难读取或修改其内容

    # 29.Virtual DOM 真的快吗，相对于直接操作DOM哪个更快？

    1. 并不快，js直接操作DOM更快
    2. 但是数据驱动要有合适的技术方案,不能全部重建DOM
    3. vdom就是目前最合适的方案（并不是因为它快，而是合适）

    # 31.说一说浏览器缓存？

    1. 首先说说缓存类型，缓存类型分为强缓存和协商缓存。强缓存的情况下，只要资源没有过期，则直接使用缓存中的资源而不会去请求服务器，通常通过HTTP响应头中的 Expries 和 Cache-control 字段来控制。而协商缓存即使资源过期了，但是仍然可能有效，会向服务器询问资源是否已更改，如果未更改就返回一个304状态码，告诉浏览器继续使用该资源
    2. 再说下缓存策略
      1. 一个是基于时间的缓存：使用Expires或Cache-Control字段指定缓存资源的过期时间。
      2. 另一个基于验证的缓存：使用Last-Modified或ETag字段来验证资源是否已更改。

    # 32.介绍一个BFC及其应用？

    1. BFC就块级格式化上下文，相当于一个独立的容器，容器的内外元素相互不影响
    2. 创建BFC的方式有浮动、定位、overflow和display表格或者弹性布局
    3. 应用有清除浮动和解决外边距重叠问题

    # 33.Vue子组件为什么不能修改父组件传递的prop

    1. 因为prop是一种单向数据流的设计原则，这样设计的原因是可以明确的知道哪些数据是父组件传递给子组件的，如果子组件也可以修改，就会造成混乱并且难以追踪。
    2. 如果要是修改某个传过来的值，应该使用触发自定义事件的方式，在父组件中来修改这个值

    # 34.讲一下HTTP握手过程

    1. HTTP握手的过程，实际上就是指HTTP在TCP/IP协议上建立连接的过程，就涉及到TCP三次握手

    2. 三次握手：确认双方收发消息是没问题的

      1. 客户端发出连接请求（服务端确认客户端有发消息能力）
      2. 服务端返回响应（客户端确认服务端有收发消息能力）
      3. 客户端再次发出确认消息，连接建立（服务端确认客户端有收消息能力）
