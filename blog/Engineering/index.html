# 一、前端工程化

# 1.概念定义

  • 前端工程化是指在前端开发过程中，将前端开发的流程、工具和规范进行统一，并使用相关技术实现自动化，包括但不限于代码编写、测试、构建、部署等环节。

# 2.实践内容

  • 开发：使用脚手架工具（如Vue/React）进行项目初始化，提供基本的项目结构和依赖管理。
  • 构建：利用构建工具（如Webpack、Rollup、Vite）对代码进行打包、压缩和优化，以减小文件体积，提高加载速度。
  • 测试：包括单元测试、e2e测试、组件测试、黑盒测试等，确保代码质量和功能正确性。
  • 部署：通过CI/CD（持续集成/持续部署）工具实现自动化部署，减少手动操作，提高部署效率。
  • 性能优化：对前端代码进行性能分析和优化，包括代码拆分、懒加载、缓存策略等，提高页面加载速度和用户体验。

# 3.技术实现

  • 规范化：通过制定开发流程规范、编码规范、版本管理规范等，统一开发标准和流程，提高团队协作效率。
  • 模块化：将功能拆分为独立的模块进行开发，实现模块级别的复用，降低研发成本和提高整体效率。
  • 自动化：基于定义的研发流程，建立一套自动化流水线，当特定动作发生（如定期触发、Git Push）时，自动触发流水线执行CI/CD任务。

# 4.工具支持

  • 代码编辑工具：如WebStorm、VS Code等，提供代码编写和编辑的支持。
  • 代码版本控制工具：如Git、SVN等，用于管理代码版本和团队协作。
  • 代码包管理工具：如npm、Yarn等，用于管理项目依赖和包版本。
  • 前端构建工具：如Webpack、Vite等，用于代码构建和打包。
  • 调试工具：如浏览器开发工具等，用于调试和测试前端代码。

# 5.意义

  • 前端工程化可以显著提高前端开发效率，降低研发成本，提高代码质量和可维护性。
  • 通过规范化、模块化和自动化等手段，前端工程化可以优化前端项目的研发、运维阶段，提升整个团队的开发能力和协作效率。

# 6.优点

  1. 提高开发效率，模块化和组件化实现逻辑复用，减少重复性工作，提高开发速度
  2. 降低沟通成本，通过代码规范和自动化工具，可以让开发人员更专注业务逻辑实现，减少不必要的沟通
  3. 代码质量提升，通过编码规范化和代码审查，保证代码的稳定性和可维护性
  4. 持续集成和部署，代码自动构建，测试和部署，减少手动操作的风险和错误，提升开发效率

# 7.缺点

  1. 学习成本较高，涉及到多个工具和技术，如webpack、eslint、prettier等
  2. 配置复杂，不同的项目，根据实际需求可能会有不同的配置，增加复杂性和难度
  3. 性能问题，复杂的配置和工具可能会导致项目启动变慢，影响开发进度

# 四、vite配置

Vite 通常的配置涉及多个方面，这些配置可以根据项目的具体需求进行调整。以下是一些常见的 Vite 配置项，以分点表示和归纳的形式进行说明：

# 1. 基础配置

  • root：项目根路径，可以是绝对路径或相对路径。
  • base：开发或生产环境服务的公共基础路径。例如，如果部署的项目在端口后面加入了虚假路径，可以通过设置这个属性来确保资源可以被正确访问。

# 2. 插件配置

  • plugins：用于配置一些第三方 Vite 支持的插件。这些插件可以增强 Vite 的功能，如支持特定框架、优化代码等。

# 3. 静态资源配置

  • publicDir：作为静态资源服务的文件夹。默认值是 public，但可以根据需要修改其路径。

# 4. 缓存配置

  • cacheDir：缓存文件目录，即 Vite 项目开发阶段的缓存存放的目录。默认值为 node_modules/.vite，但也可以修改。

# 5. 全局变量定义

  • define：用于定义全局变量。这些变量可以在整个项目中使用，而无需在每个文件中单独引入。

# 6. 路径别名配置

  • resolve.alias：用于路径别名替换。例如，可以使用 @ 符号代替 src 目录的路径，以提高开发效率。

# 7. 模块去重配置

  • dedupe：配置模块的去重规则，以减小最终构建产物的体积。例如，可以指定某些库在构建过程中进行去重。

# 8. 导入配置

  • extensions：配置导入时想要省略的扩展名列表。例如，可以配置为自动解析 .js、.ts、.jsx、.tsx 等文件，而无需在导入时指定扩展名。

# 9. 其他配置

  • mode：指定当前构建的模式，如 development 或 production。不同的模式可能会应用不同的配置选项。
  • envDir：指定环境变量文件的目录。这些文件可以包含与特定环境相关的配置选项。
  • server：配置开发服务器的选项，如端口号、主机名等。

# 10. 异步配置

  • 如果配置需要调用一个异步函数，可以导出一个异步函数。这个函数可以通过 defineConfig 传递，以便获得更好的智能提示。

# 示例配置

以下是一个简单的 Vite 配置示例：

// vite.config.js  
import { defineConfig } from 'vite'  
import vue from '@vitejs/plugin-vue'  
  
// https://vitejs.dev/config/  
export default defineConfig({  
  plugins: [vue()],  
  resolve: {  
    alias: {  
      '@': '/src'  
    }  
  },  
  server: {  
    port: 3000  
  },  
  build: {  
    outDir: 'dist'  
  }  
})

这个示例配置中包含了 Vue 插件的引入、路径别名的配置、开发服务器的端口号设置以及构建输出目录的设置。当然，具体的配置项和值会根据项目的实际需求进行调整。

# vite优化

Vite 提供了多种优化策略，以提升开发效率和生产环境的性能。以下是一些主要的优化点，按照不同的类别进行分点表示和归纳：

# 1. 构建性能优化

  • 极速构建

    ：

    • Vite 利用 esbuild 预构建依赖，使得依赖模块的热更新（HMR）变得非常快。esbuild 的操作是纳秒级别，比传统的 JavaScript 打包器快 10~100 倍。

  • 按需编译

    ：

    • Vite 采用先启动开发服务器，然后在请求某个模块时对该模块进行实时编译的方式，显著减少了编译时间，提高了开发效率。

# 2. 开发体验优化

  • 热更新（HMR）

    ：

    • Vite 支持热更新，可以在开发过程中实时更新页面，无需重新打包，大大提高了开发体验。

  • 配置简单

    ：

    • 相比于 webpack，Vite 的配置相对简单，只需要配置少量的选项即可。这使得开发者能够更快速地配置和启动项目。

# 3. 代码优化

  • Tree Shaking

    ：

    • Vite 支持 ES 模块的静态分析，因此可以利用 Tree Shaking 特性，只引入项目中实际使用的模块，减少打包体积。

  • 懒加载

    ：

    • 使用 Vue Router 的动态导入功能，将路由按需加载，可以减少初始加载的资源量，提高应用的性能。

  • 异步组件

    ：

    • 将组件按需加载，可以减少初始加载时的组件数量，提高应用的启动速度。

# 4. 资源优化

  • 代码分割

    ：

    • 使用动态导入功能分割代码，根据路由或用户操作情况按需加载代码块，减少初始加载的 JS 文件大小。

  • 图片优化

    ：

    • 使用合适的图片格式，如 WebP 格式，以提供更好的图像压缩效果。同时，可以使用懒加载或按需加载的方式来加载图片，减少初始加载时的资源请求。

# 5. 打包性能优化

  • 分包策略

    ：

    • 将不会经常更新的代码单独打包成一个 JS 文件，利用浏览器的缓存机制减少 HTTP 请求，同时降低服务器压力。

  • gzip 代码压缩

    ：

    • 在生产环境中，使用 gzip 对代码进行压缩，可以进一步减小文件体积，加快加载速度。

# 6. 使用优化插件

  • vite-plugin-html

    ：

    • 用于将传统 HTML 文件作为输出文件使用，提供了基于 html-webpack-plugin 插件的优化。

  • 图片压缩插件

    ：

    • 可以自动压缩项目中的图片资源，减少图片大小，提升页面加载速度。

# 7. 缓存策略

  • 合理使用缓存

    ：

    • 通过合理使用缓存策略和技术，如 Service Worker 和 localStorage 等，提高应用的响应速度。

综上所述，Vite 提供了多种优化策略，从构建性能、开发体验、代码优化、资源优化、打包性能优化、使用优化插件以及缓存策略等多个方面入手，帮助开发者提升项目的整体性能和开发效率。

# linters

Linters 是检查您的代码并告诉您存在任何错误的工具，它们是什么类型的错误，以及它们出现在哪些代码行上。通常，linters 不仅可以被配置为报告错误，还可以报告任何违反您的团队可能正在使用的指定样式指南的行为(例如代码使用了错误的缩进空格数)。

  • eslint
  • csslint

# 代码格式化

代码格式化程序与 linters 有些关联，除了它们不是指出代码中的错误，而是根据你的样式规则，确保你的代码被正确格式化，理想情况下自动修复它们发现的错误。

  • prettier
